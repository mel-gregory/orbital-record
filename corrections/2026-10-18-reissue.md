# Correction note — re-issue of 2026-10-13 to 2026-10-16

Date: 2026-10-18

## Summary

On 2026-10-18 the archived slices for 2026-10-13, 2026-10-14, 2026-10-15 and 2026-10-16 were re-issued. The re-issued files replace the original files for these four days; the original files are superseded. The original SHA-256 hashes are preserved in the tables below, so the original files remain identifiable. Each re-issued day was produced by the store's /record.json export, the same export the nightly exporter uses, after the day-membership fix described below.

## Root cause

Day membership was keyed on last-touch timestamps. A last-touch timestamp refreshes every time a row is updated, so a row that was still being updated moved out of the slice for the day it was first seen. Rows first seen on one of these four days but still active escaped into later slices or, for two NHC storm records (Trudy, ep212026, and Simon, ep202026), appeared in no archived day at all. The fix is worker migration 014: each row now carries a first-seen stamp (first_ingested_at for events, first_measured_at for readings and pairs) that is set once and never refreshed, and day membership keys on that stamp. With the fix in place, the four days form a disjoint partition of the rows first seen in that span.

## What is reconstructed

For rows that existed before migration 014, the first-seen stamps are reconstructed from surviving evidence and are approximate. Of the 1,286 events placed across these four days, 1,201 carry class A evidence (the earliest ingested_at the row carries in any of the original archived slices for 2026-10-13 to 2026-10-16) and 85 carry class B/C evidence (in-store evidence: link membership, product fetch times, and group observations; this class includes the two NHC records, placed on 2026-10-14). Class D, a fallback to the last-touch stamp, was needed for 0 events. Rows are placed on their best-evidenced first-seen day. A small number of rows displaced across the 2026-10-15 / 2026-10-16 boundary by the original fault cannot be individually separated from surviving evidence (for example WHO rows) and sit on their earliest evidenced day.

## CelesTrak element-set text

The original slices for 2026-10-14, 2026-10-15, 2026-10-16 each carried one tle_snapshots row whose content field was the verbatim element-set document (2,856 characters) for the 17-object 'stations' group, ingested before the 2026-10-16 fence that ended redistribution of element-set text. In the re-issued slices that content value is replaced with exactly this text:

"Element-set text withheld. This snapshot's catalog metadata and object count are recorded in this row; the snapshot document itself is not redistributed. See corrections/2026-10-18-reissue.md."

The row itself, its catalog metadata and its object count remain in place; no other byte of the document is changed by this step.

On 2026-10-13 the tle_snapshots table is empty in the re-issued slice; no replacement was applied to those days.

Whether the live endpoint still serves the element-set text was checked during this re-issue, on 2026-10-18. Finding: 2026-10-13: no tle_snapshots rows served; 2026-10-14: 1 row(s) served, content length(s) 2856 characters; 2026-10-15: 1 row(s) served, content length(s) 2856 characters; 2026-10-16: 1 row(s) served, content length(s) 2856 characters. Where a row was served with its content text present, the replacement above was applied in the re-issued file; the finding is stated as measured, with no further characterisation.

## Snapshot sections

Each day's slice carries the store's snapshot sections (stations and sources) as the endpoint serves them. In the re-issued slices those sections reflect the store at re-issue time (2026-10-18), not the original nights. The export has always carried the current snapshot; the original days carried their own nights' snapshots.

## Row content

Event and pair rows in the re-issued slices are the store's current rows, placed on their first-seen day. A row that was updated after its original night appears in its latest published state. The version-history property of the original exports — in which each day's slice stated a row as it stood that night — does not survive this re-issue for these four days.
